# v2 Display: monitor-layout + Miracast

Default branch `master` (also `v2-dev`). Physical layout comes from
[kris-1/omarchy-monitor-layout](https://github.com/kris-1/omarchy-monitor-layout)
(`docs/UPSTREAM-monitor-layout.txt`). Cast backend stays in this repo
(`miracast-ctl`, FluxCast, `MiracastService.qml`).

## Apply order

1. Physical monitors: `LayoutService.qml` / `LayoutApplier.qml` via `LayoutModel.js`.
2. Virtual Extend head: `miracast-ctl` only (park `-12000x0`, place at packed `x,y`).
3. Capture health after a virtual-head move.

## Virtual heads (layout must ignore)

`LayoutModel.isVirtualHead` / `isArrangeable` skip:

- `persistent-miracast`
- `Miracast*`
- `HEADLESS*`
- any hyprctl object with `miracast: true`

Do not write `hl.monitor` rules for those names. Do not treat them as
Win+P “external display”. Do not `output remove` them.

## Plugin ids

- Bar widget / IPC: `realchrisolin.display` (`clonedFrom: omarchy.monitor`)
- Entry: `DisplayPanel.qml` (kris-1 host + `MiracastSection.qml`; not named `Panel.qml` — that shadows `qs.Ui.Panel`)
- Layout host: `MonitorLayoutHost.qml` (child of the bar widget)
- Live install: real directory `~/.config/omarchy/plugins/realchrisolin.display` (not a symlink — Qt `createComponent` rejected new files through the old symlink). After git edits: rsync the tree there.
- v1 UI is branch `v1-legacy` (former `master`), not this branch.

## Handshake hold

`LayoutModel.shouldHoldLayout(status, lockPresent)` is true during
`connecting` / `dhcp` / `rtsp`, and while `connecting.lock` exists unless
phase is already `streaming`. `MonitorLayoutHost.qml` skips `applier.apply()` then.

Connect must not put the Extend head on a physical monitor. A new headless
output appears at `0x0`, and `monitor-layout.json` packs `persistent-miracast`
there, so `ensure_extend_monitor` slides physical monitors to their packed x
**before** `output create` (no virtual head exists yet). If the head already
exists and that packed box still intersects eDP, connect parks it at
`-12000x0` instead of placing it. After the first air-TX streaming sample,
`miracast-ctl` moves physical monitors (position-only), then
`place-virtual-head`. `place-virtual-head` refuses a target that still
intersects a physical monitor.

Disconnect and reconnect must not warp the pointer to the center of eDP.
`force_seat_to_primary` moves it only when it is on the virtual head or in
empty space, and then to the same relative spot on the laptop. Sliding a
physical monitor keeps the pointer on that monitor's same pixel. Workspace
focus during connect runs with `cursor.no_warps` so Hyprland's
`warp_on_change_workspace` does not send the pointer to the TV and back.

After a physical apply, `miracast-ctl place-virtual-head` parks an idle
Extend head or re-places a live one. No-op when geometry already matches.
**x,y-only** moves do not pause/SIGUSR1 capture (`wf-recorder -o` follows the
output name). Restarting capture on every drag rebuilt AAC+`aresample` and
brought back ~0.5 s lag.

`LayoutModel.stagingX` / `positionsToLua` stage physical outputs past both
current and packed virtual geometry, then land them. A changed Miracast head
is moved last in that eval: a rejected HEADLESS rule aborts the rest of the
script, and putting it first left eDP stacked at `0x0` (lock-screen overlap).
`place-virtual-head` repeats the move on its own when that rule does not
apply. `monitors-layout.lua` stays physical-only.

Win+P (`externalModeCommand`) ignores virtual heads.

Physical scale/rotation persist in `monitor-layout.json` and
`~/.config/hypr/monitors-layout.lua` (loaded after `monitors.lua` on reload).
Virtual heads are omitted from that lua file. SCALE pills write JSON and run
`LayoutApplier` (eval → reread → staged pack → lua). Lua is written only after
the staged move so a file-watch reload cannot skip staging. Multi-line lua is
base64 + flock so every bar copy can persist. They do not call
`omarchy-hyprland-monitor-scaling` (that sed's eDP `omarchy_monitor_scale`).

`hypr/bindings.lua` (loaded from `~/.config/hypr/bindings.lua`):
**SUPER+SHIFT+CTRL+LEFT/RIGHT** moves the focused window onto the left/right
display’s active workspace (`movewindow mon:l` / `mon:r`).
**SUPER+SHIFT+ALT+LEFT/RIGHT** still moves the whole workspace.

## Phases

- P0: this contract + `isVirtualHead` tests
- P1: `MiracastSection.qml` (scan / doctor / connect / mode / position / peers)
- P2: host section in kris-1 `Panel.qml` + persist/audio + advanced encode/radio
- P3: layout hold during handshake; `place-virtual-head` after apply/reload
- P4: Arrangement packs the Miracast HEADLESS tile in `layout.order` with
  USB-C/eDP. `place-virtual-head` uses that packed `x,y`. `extendPosition` is
  deprecated (leftover `"left"` is ignored). Double-click opens properties.
- P5 later: upstream virtual-head skip + extraSection Loader to kris-1
